# Latest Owner / Provider integration

The remaining approved Owner/Provider screens and behaviour have been ported from source checkpoint `975f201`, preserving the original design. This branch retains the integrated authentication, four-role router, shared `full_name`/`contact_number` fields, legacy property support and canonical rental-unit linkage.

## Included

- **Expired requests:** Pending requests past their response/start deadline have distinct styling and read-only Provider actions. Their saved Pending state and audit history are retained; they are not silently cancelled or reassigned.
- **Location matching:** the Owner confirms a supported service area, with an optional selected map pin. Providers maintain coverage areas. Current matches and alternative times pass server-side service/availability/location checks. Selecting an alternative requires confirmation and a new availability/quote check. Approximate distance is shown only when both valid pins are available; private Provider origins are not exposed.
- **Working time:** edit/copy slots by weekday, block unavailable dates, preflight confirmed bookings and save atomically against a revision. The backend protects confirmed jobs and concurrent edits. Workload hours are separated by day; more than two slots expand/collapse with `+more`.
- **Schedule:** the approved month calendar with selected-day jobs, swipe and arrow navigation, month-boundary handling and persistent Provider navigation.
- **Reminders:** account/project-scoped local Android reminders, permission prompts following an explicit user action, optional day-before reminders, reconciliation from current bookings, and navigation into Schedule on tap. Sign-out/account changes cancel the prior account's reminders.
- **Profile and Settings:** compact Profile header with Edit profile near the top, grouped service/workload details, fixed Save changes and unsaved-change confirmation, grouped availability, concise Notifications, immediate Appearance selection including System, password-reset sign-out confirmation, grouped Help answers and draft legal status, and confirmed sign-out for both roles.
- The existing Before-photo start gate and completion confirmation remain in place.

The shared Settings card now provides a transparent Material surface for ListTile ink; this fixes a Flutter 3.44 assertion while retaining the approved colours, border, spacing and layout. The Android callback alias now matches the existing `smartrental://auth/recovery` client configuration while retaining the older callback alias. Supabase redirect allow-list and email delivery still need hosted verification.
